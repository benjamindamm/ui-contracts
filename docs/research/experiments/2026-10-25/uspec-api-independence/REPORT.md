# uSpec: eigenständiger APIcache-Beitrag neben drei Fachquellen

Stand:25. Oktober2026. **X01 A/C538**, nur für den tatsächlich eigenständig prüfbaren ursprünglichen APIcache-/Evidence-Teilbeitrag. Drei Bedingungen P97 erfüllt. Kein unabhängig ladbarer partieller Canonical-Root behauptet.

Die tatsächliche ursprüngliche validateCacheFile-API wird gezielt für domain=api aufgerufen. Sie verlangt hierfür keinen Structure-/Color-/Voice-Cache; diese Eigenständigkeit wird tatsächlich ausgeführt, nicht aus optionalen Feldern geraten. Die ursprünglichen Envelope-/Extraction-/Ledger-Metadaten bleiben erhalten, ohne darin fremde Fachdefinitionen zu führen. Tatsächliche Obligation-Evidence liegt vor.

Interface besteht hier aus der führenden ursprünglichen CEM-Property und dem daraus abgeleiteten ursprünglichen APIcache/Fact samt konkreter bereits nachgewiesener Fremdquellenbindung. Mehrere Artefakte innerhalb derselben Domäne sind offengelegt; es werden nicht zwei unverbundene Master gepflegt. Getrennt bleiben SCXML als Behavior, CSS als Visual und HTML/ARIA als Accessibility. Der gemeinsame Canonical-Root mit seinen weiteren Pflichtfeldern ist ein anderer, hier nicht geladener Gegenstand.

Die zusätzliche semantische Verbindung ordnet APIproperty value:string dem tatsächlich ursprünglichen SCXML-Datamodel-/öffentlichen value-change-Wert zu. CEM-Teile adressieren die richtigen vorhandenen HTML-IDs und CSS-Popupziele; Name des tatsächlich gelieferten Events passt zur CEM-Eventdeklaration. Tatsächliche Original-Statechart/Parent-Lieferung statt nur ein Vergleich von Dateinamen.

| Fall | Original- und Trennungsbeobachtung |

| control | APIcache mit Evidence angenommen; tatsächliche ursprüngliche OPEN/COMMIT/Parentlieferung ergibt alpha:string; CSS160. |
| visual-revision | Nur CSS160→192 geändert; Interfacegruppe, SCXML und HTML bytegleich, tatsächlicher ursprünglicher Publicwert weiter alpha:string. |
| behavior-revision | Nur ursprüngliche SCXML-Datamodelinitialisierung alpha→beta geändert; Interfacegruppe/CSS/HTML bytegleich; tatsächlicher ursprünglicher Publicwert beta:string. |

Die unterschiedlichen Informationsrollen sind damit konkret verbunden und unabhängig änderbar, ohne Behavior-/Visual-/Accessibility-Definitionen in den APIcache zu erzwingen. Der Typebezug ist ausdrücklich primitiver value:string; keine vollständige öffentliche Payloadbibliothek, neutrale Gesamtbeschreibung oder gesamte Autocomplete-Interaktion daraus abgeleitet.

Original-Statechart-Fabriken werden pro Instanz tatsächlich frisch vorbereitet. Node meldet veraltete APIs aus den unveränderten Abhängigkeiten; die Warnungen sind keine geänderten Originalsemantiken oder Ergebnisfehler. Kein Browser-/AT-Test dieses zusätzlichen statischen Paket-/Originalruntimeversuchs. Frühere Canonical-Rootpflichten und lokale Resolvergrenzen bleiben gültig.

Reproduktion: prepare.py übernimmt exakt den separat nachgewiesenen CEM/Fact/API-Beitrag und drei Originalsyntaxfixtures; run.cjs verwendet vollständigen ursprünglichen Cachevalidator sowie tatsächliche ursprüngliche SCXML4.3.28. Keine Produktionskomponente, Commit oder Push.
