# Forschung gezielt nachlesen

**Für normale Komponentenarbeit zuerst den [Skill](../../skills/ui-contracts/SKILL.md) oder den [passenden Arbeitsweg](../README.md) verwenden.** Hier stehen Herleitungen, Entscheidungen und erhaltene Messbelege; sie gehören nicht pauschal in den Startkontext.

| Frage | Nötiger Einstieg |
| --- | --- |
| Was ist aktuell nutzbar? | [Aktueller Frameworkstand](../STATUS.md) |
| Warum vier Domänen und diese Verbindungen? | [Integrationsprofil](INTEGRATION-PROFILE.md), bei konkreten Details [Bindungsentwurf](INTEGRATION-BINDING-DRAFT.md) |
| Warum kleine Übergaben und gezielter Kontext? | [RD-001](decisions/RD-001-STAGED-GENERATION.md) und die aktuelle [Präzisierung RD-002](decisions/RD-002-AGENT-WORKFLOW-SCOPE.md) |
| Wie wurde der Agentenablauf weiterentwickelt? | [Paket 4: Workflow und Informationsarchitektur](analyses/AGENT-WORKFLOW-2026-10-31/README.md) |
| Welche konkreten Fehler und Reparaturen gibt es? | [Fehlerregister](../skills/ISSUES.md), anschließend nur den zugehörigen Beleg |
| Welche Nachweise liegen vor? | [Dokumentenindex](DOCUMENT-INDEX.md) oder [Studienübersicht](STUDIES.md) |
| Wie verlief die Entwicklung? | [Entwicklungsschritte](../EVOLUTION.md) |

`CURRENT-STATUS.md`, Matrix, Kandidatenabschluss und ältere Nachweiszähler dokumentieren ihren datierten Forschungsstand. Sie sind keine automatische Aussage über den heutigen operativen Frameworkumfang. Neue Analysen ergänzen die Historie; alte Inputs, Kriterien und Ergebnisse werden nicht nachträglich passend gemacht.

Ein kontrollierter Modellpilot kann bei entsprechendem Forschungsauftrag nützlich sein. Er bleibt von normalen Arbeitsaufträgen getrennt. Neue Forschungsergebnisse und Prüfprotokolle werden als Dateien mit Quellen-/Artefakthashes aufbewahrt; ein alter Pass ist kein aktueller Zielnachweis.
